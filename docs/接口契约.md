# 接口契约（数据层 API · 前后端共同遵守）

本项目前后端都在同一个 `index.html` 里，通过 **STORE 数据层** 解耦。前端（UI 段）只调用下面这几个函数，后端（STORE 段）负责实现，双方不直接改对方的变量。这样分工时各写各的段落，合并简单。

模块顺序：配置 → 工具(IMG/FILE/VOICE) → SafeLS → 账号 Auth → 社交 Social → 数据层 Store → 限流 Rate → 助手 AI → 界面 UI。

## 配置对象 CHAT_CONFIG（页面顶部）

| 字段 | 类型 | 说明 |
|---|---|---|
| `env` | string | 腾讯云环境 ID。留空 = 本地存储模式；填写后 = 云数据库模式 |
| `collection` | string | 云数据库集合名，默认 `chat_messages` |
| `rateWindowMs` / `rateMax` | number | 限流窗口 60000ms / 最多 8 条 |
| `pollMs` | number | 消息刷新间隔，默认 2500 毫秒 |
| `aiProxyUrl` | string | 扣子智能体云函数 HTTP 地址；留空 = 只用本地规则助手 |
| `aiTimeoutMs` | number | 等待 AI 回复超时，默认 40000 |
| `maxFileBytes` | number | 单个附件上限，默认 512*1024 |
| `maxVoiceSec` | number | 单次录音最长秒数，默认 60 |

## 消息对象结构（前端按这个字段渲染）

```js
{
  mid: 'u_xxxx',               // 消息唯一 ID（客户端生成）
  ownerId: 'u_xxxx',           // 归属者 ID（账号哈希，隔离依据）
  ownerUid: 'alice',           // 归属者账号（小写），社交关系用
  ownerName: '小明',            // 显示昵称
  content: '消息文本',          // 内容；附件消息为占位文本
  kind: 'user'|'ai'|'system',  // 类型：用户 / 助手 / 系统
  createdAt: '2026-11-23T...', // ISO 时间
  // ↓ 可选字段
  image: 'data:image/jpeg;base64,...',     // 图片
  file:  {name,size,type,data},            // 文件附件
  audio: {data,dur,mime,bytes},            // 语音
  dm: true, toUid:'bob', toName:'小红'      // 私聊（三字段同时出现）
}
```

## STORE 接口（后端实现，前端调用）

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `Store.init()` | 无 | Promise | 有 env 则初始化云 SDK + 匿名登录，否则本地模式 |
| `Store.list()` | 无 | Promise<记录数组> | 按时间升序返回全部记录（云端含 `kind=profile / social` 辅助记录，`refresh()` 会先吸收再过滤） |
| `Store.add(msg)` | 消息对象 | Promise | 新增一条消息（本地模式串行写入，避免并发覆盖） |
| `Store.remove(mid, ownerId)` | 消息 ID、当前身份 ID | Promise | 删除消息，内部校验 ownerId，只能删自己的 |

- 云端实现：`cloudbase` SDK 的 `db.collection(...).add / get / where / doc().remove()`
- 本地实现：SafeLS 多后端降级（键 `spark_chat_messages_v1`）
- 两者对上层接口完全一致，前端无需关心当前是哪种模式。

## 统一发送函数 send（前端唯一入库入口）

| 方法 | 参数 | 返回 |
|---|---|---|
| `send(text, kind, image, extra)` | 文本、类型、图片 dataURL(可空)、附加对象(可空) | `Promise<true / false>`（false = 被限流） |

- `extra` 可含 `{file, audio, dm:{to,toName}}`，统一挂到消息对象上。
- `send` 内部依次做：`Rate.check` → 组装消息 → `Store.add` → `refresh` → 返回 true。
- **所有发送路径（文本 / 图片 / 文件 / 语音 / 私聊）都经过它**，保证限流与归属隔离一致。

## 账号 AUTH（登录界面）

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `Auth.register(account, password, nickname)` | 账号、密码、昵称(选填) | `{ok:true, me}` 或 `{ok:false, error}` | 新建账号；已存在则报错 |
| `Auth.login(account, password)` | 账号、密码 | `{ok:true, me}` 或 `{ok:false, error}` | 校验；账号不存在或密码错则报错 |
| `Auth.directory()` | 无 | `[{uid,username,nickname,createdAt}]` | 用户目录（不含密码），供好友搜索 |

- 账号表 `spark_chat_users_v1` 存 `{账号:{pass:哈希, nickname, createdAt}}`，不存明文。
- `me` 结构：`{id, username, uid, nickname}`。`id` 由**小写账号**哈希生成（ownerId），`uid` 为小写账号（社交用），跨设备一致。
- 约定：密码至少 4 位；账号不区分大小写。
- **云端模式**：注册时额外写一条 `kind=profile` 记录到云端集合；`login()` 本机查不到时会用云端目录校验密码；`directory()` 合并本机账号与云端目录，因此能搜到**别的设备注册的账号**。

## 社交 SOCIAL（好友与私聊）

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `Social.request(me, peer)` | 双方身份 | `{ok, auto?}` / `{ok:false,error}` | 发好友申请；重复申请、已是好友会拦截；对方也申请过则自动互加 |
| `Social.respond(reqId, me, accept)` | 申请 ID、我、是否同意 | `{ok}` | 同意则写入好友关系 |
| `Social.remove(me, peerUid)` | 我、对方账号 | `{ok}` | 删除好友并清理相关申请 |
| `Social.friendsOf(me)` | 我 | `[{uid,nickname}]` | 我的好友列表 |
| `Social.incoming(me)` / `outgoing(me)` | 我 | 申请数组 | 收到 / 发出的待处理申请 |
| `Social.isFriend(a, b)` | 两个 uid | boolean | 是否已是好友 |

- **本地模式**：整份关系存 `spark_chat_social_v1`，即 `{requests:[...], friends:[...]}`，同步读写。
- **云端模式**：`Social.data()` 改由 `CloudSync.state()` 提供（同一结构），写操作改为 `CloudSync.push()` 追加 `kind=social` 事件；查询接口、返回值、调用方完全不变（前端无感知）。
- **私聊消息不是独立表**，而是主消息流里带 `dm:true` + `toUid` 的记录，复用 STORE/限流/归属隔离；云端模式下自然跨设备可见。
- `refresh()` 按 `state.scope` 过滤：`all` 严格排除 `dm` 与 `profile/social`；`dm` 只取双方互发；`mine` 按 ownerId；`db` 只列聊天消息；`friends` 渲染好友面板。

## 云端同步 CloudSync（后端段，仅云端模式生效）

| 方法 | 返回 | 说明 |
|---|---|---|
| `CloudSync.absorb(list)` | 无 | `refresh()` 每轮轮询调用，把集合里的 `profile` / `social` 记录吸收到内存缓存 |
| `CloudSync.publishProfile(rec)` | 记录 | 注册/老账号迁移时写 `kind=profile`，并立即更新缓存 |
| `CloudSync.publishLocalUsers()` | 无 | 启动时把本机已有账号补进云端目录（先 absorb 再去重，避免重复写） |
| `CloudSync.push(act)` | 事件 | 追加 `kind=social` 事件；立即进 `pending` 缓存让本机界面即时响应，写入失败只告警 |
| `CloudSync.state()` | `{requests, friends}` | 把 `events + pending` 按 `createdAt` 重放成与本地 `Social.data()` 同构的状态 |

- **append-only 事件流**：`act` 为 `request / accept / reject / friend / remove`。两台设备并发写不会像「读整份 → 改 → 写回」那样互相覆盖。
- 所有查询函数保持**同步**，靠内存缓存供数；跨设备一致性由 2.5 秒轮询的 `absorb()` 保证。
- 复用同一个 `chat_messages` 集合，不需要新建集合，也不新增控制台配置项。

## 附件工具（后端段）

| 工具 | 方法 | 说明 |
|---|---|---|
| `IMG.read(file)` | → `{dataURL,w,h,bytes}` | canvas 压缩图片，只产出 `data:image/` 前缀 |
| `FILE.read(file)` | → `{name,size,type,data}` | 任意文件转 base64，带体积保护 |
| `VOICE.start()` / `stop()` / `cancel()` | → Promise | `MediaRecorder` 录音；`supported()` 为 false 时上层降级为音频文件上传 |

- 渲染时附件 base64 放进 `ATT_CACHE`，DOM 只留 `data-dl` / `data-play` 标记，避免巨型字符串进 innerHTML。
- 只信任 `data:` 前缀的文件名/内容都 `esc()` 转义，下载用 `<a download>`，不执行内容。

## 限流 RATE

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `Rate.check(ownerId)` | 身份 ID | `{ok:true}` 或 `{ok:false, wait:秒数}` | 滑动窗口，超限返回需等待秒数 |

存储键 `spark_chat_rate_v1`；前端发送前先调用，超限则阻止并显示提示。

## 智能助手 AI

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `AI.answer(question, userId, history)` | 问题、用户 ID、最近对话 | `Promise<回答文本>` | 配了 `aiProxyUrl` 优先调扣子云函数，失败/超时自动降级 `AI.localAnswer(q)` 本地规则 |
| `AI.localAnswer(q)` | 问题 | 回答文本 | 8 条关键词规则，离线可用 |

- `@小星` 触发：`hasMention()` / `cleanMention()`；`buildHistory()` 从消息流取最近 10 条本人+小星消息作上下文（**排除私聊与附件占位**）。
- 云函数 `cloudfunctions/aiProxy/` 走 `async_run` + 轮询 task，历史拼进 prompt，详见 `docs/扣子智能体接入指南.md`。

## 约定

- 前端不直接读写 `cloudbase` / 底层存储键，统一走 Store / SafeLS。
- 前端不绕过 `send()` 与 `Rate.check` 发消息。
- 所有消息内容用 `esc()` 转义后再渲染，防止 XSS。
- 字段名大小写严格一致（驼峰：ownerId / ownerUid / ownerName / createdAt / toUid / mid）。
- 新增功能优先扩展 `send.extra`，不要另开入库通道，避免限流/隔离被绕过。
