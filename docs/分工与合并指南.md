# 两人分工与合并指南（腾讯云网站托管版）

## 一、这套版本的组成

```
chatroom_local/
├── index.html      ← 唯一的程序文件：样式 + 界面 + 数据层 + 社交 + AI 全内嵌
├── cloudfunctions/
│   └── aiProxy/    ← 扣子智能体云函数（可选，Node.js 无依赖）
│       ├── index.js  package.json  server.js  scf_bootstrap
└── docs/           ← 文档（两人共同维护）
    ├── 腾讯云开发部署指南.md   ← 拿域名的完整步骤
    ├── 扣子智能体接入指南.md   ← 接真大模型的步骤
    ├── 扣子智能体提示词.md
    ├── 接口契约.md
    ├── 数据库说明.md
    ├── 运行说明.md
    └── 分工与合并指南.md
```

只有一个 `index.html` 是主程序，双击就能在本地打开体验；上传到腾讯云开发「静态网站托管」后就有正式域名，老师打开网址即可检查，**不需要后端脚本、不需要双击启动、不需要装数据库**。新增的图片/文件/语音/加好友/私聊全部内嵌在这一个文件里。

## 二、分工边界（同一个文件，按注释段落分工，零冲突）

`index.html` 里的代码按注释分成了清晰的段落，两人各改各的：

| 负责人 | 负责代码段（在 index.html 内搜索注释定位） | 职责 |
|---|---|---|
| **同学 A（前端）** | `/* ===== 样式 ===== */`（含「设计系统 v2 / 组件 / 动效 / 数据库多表 / 13 套气泡装扮 / 表情面板 / 悬浮角色」）+ `/* ===== 界面 UI ===== */`（`render / renderDb / renderFriends / switchScope / 装扮面板 / 表情包 / 悬浮小星 / 事件绑定`）+ SVG 图标精灵 | 页面美观与布局、亮/暗主题、SVG 线性图标、消息入场与微交互、气泡精修与 13 套可切换装扮、悬浮智能体角色与标签动作、Emoji / 萌宠表情包、Toast/确认框、空状态插画与骨架屏、文件卡片/语音条/好友面板渲染、数据库三张表视图、响应式适配 |
| **同学 B（后端/数据）** | `CHAT_CONFIG`、`IMG / FILE / VOICE`、`SafeLS`、`Auth`、`Social`、**`CloudSync`**、`Store`、`Rate`、`AI` | 云数据库读写、双模式切换、账号与好友关系（含跨设备上云）、owner_id 隔离、限流、附件编码、扣子 AI、环境 ID 配置 |

两人通过 `docs/接口契约.md` 对齐：前端只通过 `Store.list() / Store.add() / Store.remove()` 与统一入口 `send(text,kind,image,extra)` 存取数据，后端只负责实现它们，谁都不改对方的段落。

本次新增三个功能的分工落地：
- **上传文件**：后端 `FILE.read` + `send.extra.file`；前端 `render()` 文件卡片 + 下载按钮。
- **语音聊天**：后端 `VOICE.start/stop` + `send.extra.audio`；前端语音气泡 + 播放按钮；无麦克风时前端按后端 `supported()` 结果走降级提示。
- **加好友/私聊**：后端 `Social` 全套 + `send.extra.dm`；前端 `renderFriends()` 面板 + `scope='dm'` 视图 + `switchScope`。
- **跨设备同步**：后端新增 `CloudSync`（`kind=profile / social` 事件流 + `absorb/state/publish*`），`Auth` 与 `Social` 加云端分支；前端只需在 `refresh()` 里先 `absorb()` 再过滤记录、`renderFriends()` 按模式切换说明文案。查询接口全部保持同步，前端调用方零改动。
- **视觉精修包（全部由同学 A 完成，后端零改动）**：`<head>` 里的主题引导脚本 + `<style>` 追加的「设计系统 v2 / 组件 / 动效」三段 + body 开头的 SVG 图标精灵 + `界面 UI` 段新增的 `toast / confirmBox / applyTheme / initTheme / toggleTheme / avatarClass / timeLabel / emptyHTML / skeletonHTML / rippleDelegate`；`render()` 内加 `SEEN`（只给新消息播动画）、`LAST_SCOPE`（切视图回到底部）、时间分组、连续消息合并、头像配色与「正在输入」气泡。原有 `alert/confirm` 全部换成页面内组件，语音按钮改为更新 `#voiceLabel`。
- **气泡装扮 13 套 + 数据库三表 + 悬浮小星 + 表情包（同样由同学 A 完成，后端只加 1 行 `send.extra.sticker`）**：`<style>` 末尾追加 `html[data-bubble^="cute-"]` 卡通造型皮肤（`--bub-other/--bub-mine/--bub-frame/--bub-text` 四变量 + `.bd` 装饰元素）、商城式三列网格面板、表情面板、悬浮角色样式；`<head>` 引导脚本白名单加 `cute-*` 防闪；`界面 UI` 段新增 `BUBBLE_STYLES / CUTE_DECO / cuteDeco / bubbleHTML / applyBubble / renderBubblePop`、`STICKERS / stickerSVG / renderStickerPop / insertEmoji / sendSticker`、`PET_ACTS / cyclePet / initPet / hidePet / showPet / petQuickAsk`，`renderDb()` 拆成 `dbTable / dbUsersHTML / dbSocialHTML` 并加三表切换（`state.dbTab`）。
  - **后端唯一改动**：`send()` 里加一行 `if(extra.sticker && STICKER_BY_ID[extra.sticker]) msg.sticker = extra.sticker;`，以及 `buildHistory()` 跳过 `[表情包]` 占位；`Store / Rate / Auth / Social / CloudSync` 全部零改动。
  - 表情包**只存白名单 id**（不存 SVG / base64），数据库体积几乎不增加，渲染时由本地 SVG 生成器画出；悬浮小星是纯前端展示组件，与 AI 云函数通过现成的 `@小星` 触发词衔接。

四段都在各自负责的代码段内，合并时不会互相覆盖。视觉改动只碰样式与渲染层，数据层接口（`Store` / `send` / `Auth` / `Social` / `CloudSync`）保持原样。

> 说明：把代码放在一个文件里是为了"双击即用、上传即上线"零配置。两人若各自本地开发，用 Git 的不同分支改不同段落，合并时按段落粘贴即可；因为约定了各自的注释区块，不会产生逻辑冲突。

## 三、分开做的方法

1. 两人各复制一份 `index.html` 到自己的电脑。
2. 前端同学：只改 `<style>` 段和 `UI` 段，可以先用本地模式（env 留空）看效果。
3. 后端同学：只改 `STORE / RATE / AI / CHAT_CONFIG` 段，本地模式下也能测通所有逻辑。
4. 谁都不用配数据库密码、不用装环境——本地模式用浏览器存储，云端模式用腾讯云免费额度。

## 四、合并方法（三种，任选）

### 方法 A：按段落拼接（最简单，推荐）
两人把各自改好的段落发过来，按注释标记拼回一个 `index.html`（前端段 + 后端段各取一份）。因为分工按段落划定，不会丢代码。

### 方法 B：Git 分支（规范，能体现协作过程）
```bash
git checkout -b feat/frontend   # 同学 A：只改样式/UI 段
git checkout -b feat/data       # 同学 B：只改 STORE/RATE/AI/配置段
# 各自提交后合并到 main，按段落解决少量行级冲突
git checkout main
git merge feat/frontend
git merge feat/data
```

### 方法 C：腾讯文档/网盘接力
把 `index.html` 放共享文档，两人按各自段落编辑，实时同步。

## 五、给老师演示的建议流程

1. **先讲架构**：前端（原生 HTML/CSS/JS 单文件）+ 腾讯云后端（静态托管 + 云数据库 + 匿名登录 + 云函数），发布后有正式域名。
2. **打开网址**：用浏览器打开部署拿到的 `https://....app.tcloudbase.com`，说明"无需安装、无需启动脚本"。
3. **账号登录**：登录页有「立即注册」，新用户先注册（账号+密码+确认密码+昵称）；密码哈希存储，不存明文。
4. **群聊与多媒体**：发文本、「图片」、「文件」（点下载）、「语音」（录音或上传音频文件），说明每条都带 `owner_id`。
5. **加好友与私聊**：侧栏「好友」→ 找人 → 发申请 → 同意 → 私聊。强调**群聊大厅看不到私聊消息**（`dm` 字段过滤）。发布上线后用**两台设备**（电脑 + 手机）打开同一网址、各注册一个账号，等 2~3 秒即可互相搜到并加好友——这是真跨设备，比换账号切换更有说服力；本地模式则演示「注册 A → 退出 → 注册 B」的闭环。
6. **个人视图**：切到该视图，展示按 owner_id 严格隔离。
7. **删除权限**：只能删自己的消息（别人消息无删除按钮）。
8. **限流**：连续快速发超过 8 条，展示"请 N 秒后再试"提示。
9. **智能助手**：消息里带 `@小星` 发出，问"这个项目是什么架构"，展示真大模型回复与上下文记忆。
10. **展示数据**：页面内「数据库」视图直接看字段（含 attachment / scope），再到腾讯云控制台 → 数据库 → `chat_messages` 集合看云端真实记录，指出集合里还有 `kind=profile`（账号目录）与 `kind=social`（好友关系事件）两类记录——**这正是跨设备加好友能成立的原因**；说明未配 env 时自动用浏览器本地存储，两种模式一键切换。
11. **讲安全**：owner_id 隔离、私聊过滤、限流、`esc()` 输出转义、附件只信任 `data:` 前缀、匿名登录。
12. **界面与主题**：点右上角圆形按钮切换亮 / 暗主题，刷新后选择仍保持；依次展示 SVG 统一图标、新消息淡入、发送反馈、小星「正在输入」动画、时间分组与按昵称生成的头像配色、删除时的自定义确认框（不再是浏览器原生弹窗）；用手机打开同一网址展示响应式图标栏。
