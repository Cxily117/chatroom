# 后端接口文档（Express API）

后端代码在 `server/`，是独立于前端 `index.html` 的一层服务：注册、登录、发消息、删消息、加好友的**校验和归属判定都在服务端完成**，前端只发 HTTP 请求、不直接读写数据库。

前端通过 `index.html` 顶部配置的 `apiBase` 指向这个服务；`apiBase` 留空或后端探测失败时，自动退回原来的本地 / 云数据库模式。

---

## 一、启动方式

### 本机调试

```bash
cd server
npm install
PORT=8080 DB_DRIVER=file node index.js
```

数据落在 `server/data/db.json`（已被 `.gitignore` 忽略），重启不丢，改代码改数据都方便。

### 云托管部署

见 `docs/云托管部署指南.md`。要点：**服务端口 80、目录指向 `server`、`DB_DRIVER=cloudbase`**。

## 二、身份认证

登录 / 注册成功后，服务端返回 `token`：

```json
{ "ok": true, "me": { "id": "u_xxxx", "username": "alice", "uid": "alice", "nickname": "爱丽丝", "token": "alice.1764...==" } }
```

`token` 是 `uid.时间戳.HMAC-SHA256签名`，有效期 30 天。后续请求带上：

```
Authorization: Bearer <token>
```

**服务端只认 token，不认请求体里自报的 uid**：

- 发消息时 `ownerUid` / `ownerId` / `ownerName` 全部由 token 重新计算，前端传了也会被覆盖；
- 删消息时比对消息的 `ownerUid` 与 token 身份，删别人的返回 403；
- 加好友时申请方向以 token 为准，冒充别人发申请会被忽略。

签名密钥来自环境变量 `TOKEN_SECRET`，**上线务必换掉默认值**。

## 三、接口清单

所有响应都是 JSON，成功带 `"ok": true`，失败带 `"ok": false` 和中文 `error`。

### 1. 健康检查

```
GET /api/health
```

```json
{ "ok": true, "driver": "file", "collection": "chat_messages", "users": 2, "messages": 8, "uptime": 12 }
```

部署后第一件事就是打这个接口，确认容器活着、连的是哪个存储。

### 2. 注册

```
POST /api/register
{ "account": "alice", "password": "123456", "nickname": "爱丽丝" }
```

| 情况 | 状态码 | error |
|---|---|---|
| 成功 | 200 | — |
| 账号格式不合法（非字母数字下划线、长度不在 2~32） | 400 | 账号只能是字母、数字、下划线，2~32 位 |
| 密码少于 4 位 | 400 | 密码至少 4 位 |
| 账号已存在 | 409 | 该账号已存在，请直接登录 |

### 3. 登录

```
POST /api/login
{ "account": "alice", "password": "123456" }
```

账号不存在 → 404；密码错误 → 401。密码哈希只在服务端比对，**不会下发给前端**。

### 4. 全量同步

```
GET /api/sync
```

```json
{
  "ok": true,
  "users": [{ "uid": "alice", "username": "alice", "nickname": "爱丽丝", "createdAt": "..." }],
  "social": { "requests": [...], "friends": [...] },
  "messages": [...],
  "me": "alice"
}
```

前端每 2.5 秒轮询一次这个接口：一次请求同时刷新**账号目录、好友关系、聊天消息**，然后重绘界面。

`users` 里**没有 pass 字段**——这是后端模式和本地模式最大的区别，账号表视图里密码列会显示「—」。

### 5. 发消息

```
POST /api/messages
Authorization: Bearer <token>

{ "mid": "u_xxx", "content": "你好", "kind": "user" }
```

`kind` 可选 `user` / `ai` / `system`：

- `user`：必须带 token，归属字段由服务端填；
- `ai` / `system`：允许不带 token（用于 AI 回复与系统欢迎语）。

附件字段（可选，服务端会校验前缀）：`image`（`data:image/*`）、`audio`（`{data,dur,mime,bytes}`）、`file`（`{name,size,type,data}`）、`sticker`、`dm`+`toUid`+`toName`。

无 token 发 `user` 消息 → 401；内容为空 → 400。

### 6. 删消息

```
DELETE /api/messages/:mid
Authorization: Bearer <token>
```

消息不存在 → 404；删别人的 → 403；系统消息 → 403。

### 7. 加好友 / 处理申请 / 删好友

```
POST /api/friends/request   { "to": "bob" }            Authorization: Bearer <token>
POST /api/friends/respond   { "reqId": "r_xxx", "accept": true }
POST /api/friends/remove    { "peer": "bob" }
```

- `request`：不能加自己（400）、对方不存在（404）、已是好友（409）、重复申请（409）；**如果对方已经向我申请过，直接返回 `{"ok":true,"auto":true}` 并互相成为好友**。
- `respond`：只有接收人能处理（否则 403），处理过的申请不能重复处理（409）。
- `remove`：同时清掉双方相关的申请记录。

## 四、存储驱动

| `DB_DRIVER` | 数据落在哪 | 适用 |
|---|---|---|
| `file` | `server/data/db.json` 单个 JSON 文件 | 本机开发、断网演示 |
| `cloudbase` | 云开发云数据库集合 `chat_messages` | 云托管部署，容器重建不丢数据 |

两种驱动用的是**同一套数据结构**，云数据库里靠 `kind` 区分记录类型：

| `kind` | 含义 |
|---|---|
| `profile` | 账号目录：`uid / username / nickname / pass 哈希 / createdAt` |
| `social` | 好友关系事件流（append-only）：`act=request/accept/reject/remove` |
| `user` / `ai` / `system` | 聊天消息本体 |

好友关系用事件流而不是直接改状态，是为了并发安全：两个人同时点同意也不会互相覆盖，服务端重放事件后得到唯一结果。

## 五、已知边界（课堂演示够用，正式产品要补）

1. **token 不刷新**：30 天内有效，没有 refresh 机制，也没有作废列表。
2. **CORS 默认放开**：`ALLOW_ORIGIN=*`，正式部署应改成你的前端域名。
3. **全量同步**：`/api/sync` 一次返回全部消息（上限 1000 条），量大时应改成分页 / 增量拉取。
4. **无频率限制**：限流目前还在前端（60 秒 8 条），服务端没做，改接口直连可绕过。要严谨应挪到服务端。
5. **单实例内存态**：启动时把数据读进内存，多实例水平扩容会出现数据不一致。
