# 数据库说明（腾讯云开发版 · 双模式）

## 一、数据存在哪（两种模式自动切换）

| 模式 | 触发条件 | 数据位置 | 适用 |
|---|---|---|---|
| **云数据库**（发布后） | `index.html` 顶部 `env` 填了腾讯云环境 ID | 腾讯云开发 → 数据库 → `chat_messages` 集合（消息 + 账号目录 + 好友关系） | 正式上线，多设备共享、可跨设备加好友 |
| **本地存储**（默认） | `env` 留空 | 浏览器存储，按 `localStorage → sessionStorage → Cookie → window.name → 内存` 自动降级（键 `spark_chat_messages_v1`、`spark_chat_users_v1`） | 预览面板、直接双击打开、本地调试 |

设计目的：任何环境都能完整点击体验，不会因为没配云端就"点不了"；发布时只改一行 env 即切换到真实云数据库。页面底部会实时显示当前是哪种模式及具体存储介质。

**关于预览面板**：预览面板常禁用 `localStorage`，此时程序自动降级到 `window.name` 等，账号/消息在同一标签页刷新后仍保留；但如果完全换标签页/清缓存，本地数据会丢失（这是纯前端无后端的固有限制，发布到云端后消息存云数据库，无此问题）。

## 二、集合结构 chat_messages（云数据库）

| 字段 | 说明 |
|---|---|
| `_id` | 云数据库自动生成 |
| `mid` | 消息业务 ID（客户端生成，删除时用） |
| `ownerId` | **归属者 ID（由账号稳定生成，隔离依据）** |
| `ownerUid` | 归属者账号（小写），社交关系用它，避免大小写歧义 |
| `ownerName` | 发送者昵称 |
| `content` | 消息内容（附件消息为 `[图片]/[文件] 名称/[语音] 时长″` 占位） |
| `kind` | user / ai / system / **profile**（账号目录）/ **social**（好友关系事件） |
| `image` | 可选。图片 base64 dataURL（canvas 压缩后） |
| `file` | 可选。文件附件 `{name,size,type,data}`，data 为 base64 dataURL |
| `audio` | 可选。语音 `{data,dur,mime,bytes}`，data 为 base64 dataURL |
| `sticker` | 可选。**表情包白名单 id**（如 `cat` / `bunny`），只存 id 不存图形；渲染时由前端本地 SVG 生成器画出，数据库视图 attachment 列会显示 `sticker/cat` |
| `dm` | 可选。为 `true` 表示私聊消息 |
| `toUid` / `toName` | 可选。私聊接收者账号 / 昵称 |
| `createdAt` | ISO 时间字符串，按它升序展示 |

- 不需要手动建字段，写入时自动生成。
- 集合需先建好，权限建议「所有用户可读写」（课堂演示，保证多人能互相看到消息）。
- **附件走 base64**：本地存储容量有限，所以做了体积上限（`maxFileBytes` 默认 512KB，受限存储再降到 180KB）。云端模式可放宽，但腾讯云开发单条文档也有大小上限，课堂演示传小文件即可。
- **私聊消息与群聊消息存在同一集合**，靠 `dm`/`toUid` 区分。群聊大厅渲染时严格过滤 `!m.dm`，私聊视图只显示双方互发的记录。
- **账号目录与好友关系也存同一集合**（云端模式），用 `kind` 区分，不额外建集合：
  - `kind=profile`：`{uid, username, nickname, pass, createdAt}` —— 注册时写一条，`pass` 是哈希不是明文。`Auth.directory()` 从这里拿到「别的设备注册过的账号」，登录也能用云端目录校验。
  - `kind=social`：`{act, reqId, from, fromName, to, toName, a, b, ...}` —— **append-only 事件流**，`act` 为 `request / accept / reject / friend / remove`。两台设备同时操作也不会互相覆盖；`CloudSync.state()` 按 `createdAt` 重放成 `requests/friends`，所有查询函数保持同步。
  - 每次 `refresh()`（2.5 秒轮询）会先 `CloudSync.absorb()` 吸收这两类记录到内存缓存，再把它们从聊天消息里过滤掉，所以不会显示成气泡。页面内「🗄 数据库」视图也只列聊天消息，并在顶部说明云端另有这两类记录。
  - 读取用 `.limit(1000)`（云开发客户端 SDK 上限即 1000），课堂演示规模足够。

## 二·补充、好友关系表

- **本地模式**：整份关系存在浏览器 `spark_chat_social_v1`（见下表）。
- **云端模式**：不读这份本地表，改由上面的 `kind=social` 事件流重放得到；两台设备看到同一份关系。

| 字段 | 说明 |
|---|---|
| `requests` | 好友申请 `[{id, from, fromName, to, toName, status, createdAt}]`，status: pending / accepted / rejected |
| `friends` | 好友关系 `[{a, b, aName, bName, createdAt}]`，成对保存，双方便于查询 |

- 关系用稳定的账号 `uid` 标识，与消息 `ownerId` 解耦。
- 重复申请会被拦截；若对方已向你发过申请，直接互加（避免两边各点一次）。
- **边界**：本地模式下账号表与好友关系都存浏览器本机，所以「找人」只能搜到本机注册过的账号；填 `env` 发布到云端后，账号目录与好友关系自动同步到云端集合，即可跨设备互相发现、加好友、私聊（约 2~3 秒同步一次）。

## 三、怎么查看数据

- **界面内直接看（推荐演示）**：进入群聊后点左侧「🗄 数据库」，顶部有三张表可切换：
  - **① 消息表**：底层存储的全部聊天消息原始记录（mid / owner_id / owner_name / kind / content / attachment / scope / created_at），显示当前数据源。附件会标出 `image` / `file` / `audio`，私聊行会标「私聊→某人」。
  - **② 账号表（登录/注册）**：账号 uid、昵称、**遮罩后的密码哈希**、数据来源（本机 / 云端 / 两者）、注册时间。用来直观回答「账号密码有没有数据库」——有，但**不在消息表里**，是独立的一张表；密码只存哈希不存明文。
  - **③ 好友关系表**：好友申请（发起人、接收人、状态、时间）与好友关系（账号 A/B、建立时间）。
  - 三张表口径一致，老师检查时一起看最直观。
- 云端：腾讯云开发控制台 → 你的环境 → 数据库 → `chat_messages` 集合，直接看到所有消息记录，以及 `kind=profile`（账号目录）、`kind=social`（好友关系事件）两类辅助记录。
- 本地：浏览器 F12 → Application → Local Storage → `spark_chat_messages_v1`（若降级到 window.name，看页面内「数据库」视图即可）。

## 四、安全设计对应表

| 需求 | 实现方式 |
|---|---|
| 账号登录 | 本地账号表 `spark_chat_users_v1` 存哈希密码（不存明文）；云端模式账号目录 `kind=profile` 同样只存哈希，登录可用云端目录校验；独立注册页创建账号，ownerId 由账号生成 |
| 跨设备加好友 | 云端模式把账号目录与好友关系写进同一集合；好友关系用 append-only 事件流，避免多设备并发写互相覆盖 |
| 按用户隔离 | 每条消息带 `ownerId`；「个人」视图按 ownerId 过滤；删除时校验 `where({mid, ownerId})`，只能删自己的 |
| 私聊隔离 | 私聊消息带 `dm`+`toUid`；群聊大厅 `filter(!m.dm)`，私聊视图只取双方互发；AI 上下文也排除私聊 |
| 频率限制 | 滑动窗口，每身份 60 秒最多 8 条，超限提示等待秒数（群聊/私聊/附件共用同一限流） |
| 附件安全 | 只信任 `data:` 前缀的 base64；文件名/类型 `esc()` 转义；下载用 `<a download>` 不执行内容 |
| 防注入 | 云数据库 SDK 参数化写入，不拼接查询串 |
| 防 XSS | 前端 `esc()` 转义后再渲染消息 |
| 身份稳定 | ownerId 由账号哈希生成，同账号跨刷新/跨设备保持一致 |

> 说明：本地模式下账号表存在当前浏览器，换浏览器需用同账号重新注册或注册新账号。发布到云端后，消息、账号目录、好友关系、私聊都进同一 `chat_messages` 集合：两台设备打开同一网址即可共享数据、互相加好友；同账号在不同设备登录时 ownerId 一致（由小写账号哈希生成）。腾讯云匿名登录用于云 SDK 初始化，与账号登录体系互不冲突。
>
> 安全取舍（课堂演示）：集合权限设为「所有用户可读写」，因此 `kind=profile` 里的**密码哈希**对访问者可读。存的是哈希不是明文，且不含其他个人信息；若用于正式产品，应改为云函数 + 服务端校验密码，不要把账号目录直接暴露给前端。
