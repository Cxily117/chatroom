# 星火聊天室 · 扣子智能体接入指南

> 目标：把「小星」从本地规则升级成真正的扣子智能体。
> 原则：**Token 不进浏览器、不进前端代码，只在云函数环境变量里。**
> 前端未配置云函数地址时自动用本地规则，断网也能完整演示。

---

## 一、整体链路

```
用户输入问题
   ↓  POST { question, userId }
浏览器 index.html
   ↓  fetch(aiProxyUrl)
腾讯云云函数 aiProxy  ←  Token / project_id / 域名 从环境变量读
   ↓  POST /async_run  →  GET /task/{task_id} 轮询
扣子智能体（已部署为 API 服务）
   ↓  答案原路返回
云函数 → 前端 → Store.add({ kind:'ai' }) 入库 → 页面刷新显示
```

AI 回复和群消息存在同一张表 `chat_messages`，只是 `kind='ai'`、`ownerId='ai'`，
所以点「数据库」视图能看到完整记录，答辩时可以现场展示。

---

## 二、扣子侧配置（约 10 分钟）

### 1. 确认智能体已部署为 API

在扣子编程（code.coze.cn）：项目开发 → 你的智能体 → 右上角**发布** → 勾选 **API** → 发布。

### 2. 贴入提示词

把 `docs/扣子智能体提示词.md` 里的全部内容复制到「人设与回复逻辑」框。
改提示词后必须**重新部署一次**才会生效。

### 3. 拿到三个值

进入**部署 → 总览 → 某条部署记录右侧「更多」→「查看」→「API 请求示例及接口说明」**：

| 值 | 位置 | 示例 |
|---|---|---|
| API 域名 | 页面顶部请求地址里的 host | 例如 `rv43qdjg.coze.site`（以你页面实际显示为准） |
| project_id | Body params 里的 `project_id` | 19 位纯数字 |
| API Token | 同页「管理 API Token」→「创建 API Token」 | 只显示一次，立刻复制 |

> API Token 永久有效；每个项目最多 10 个。若怀疑泄露，删掉重建即可，前端无需改动。

---

## 三、腾讯云侧配置（约 20 分钟）

### 1. 创建云函数

腾讯云开发控制台 → 你的环境 → **云函数** → 新建，配置：

- 函数名称：`aiProxy`
- 运行环境：`Node.js 16` 或更高
- 创建方式：空白函数
- 把本仓库 `cloudfunctions/aiProxy/` 下的 `index.js` 和 `package.json` 上传（或粘贴代码）

### 2. 配置环境变量

在云函数「函数配置 → 环境变量」里加三项：

| 变量名 | 值 | 说明 |
|---|---|---|
| `COZE_API_TOKEN` | 上一步复制的 Token | 密钥，不要写进代码 |
| `COZE_PROJECT_ID` | 19 位纯数字 | 不要带引号、不要带空格 |
| `COZE_DOMAIN` | 你扣子部署页的实际域名 | **不带** `https://`，不带结尾斜杠 |

可选：`COZE_TIMEOUT_MS`（默认 30000）、`COZE_POLL_MS`（默认 1000，扣子要求 ≥1 秒）。

### 3. 开通 HTTP 访问服务

云函数详情页 → **触发管理** → 创建 HTTP 访问服务 → 记录生成的地址，形如：

```
https://xxx-xxx.service.tcloudbase.com/aiProxy
```

> 这个地址就是要填回前端的 `aiProxyUrl`。

### 4. 自测云函数

在云函数「测试」页，用如下事件体点测试：

```json
{ "httpMethod": "POST", "body": "{\"question\":\"来个话题\",\"userId\":\"u_test\"}" }
```

正常返回 `{"ok":true,"answer":"……"}`。若返回 `ok:false`，看返回里的 `error` 字段：
- `4101` / 鉴权失败 → Token 或权限不对
- `未返回 task_id` → project_id 或域名填错
- `等待超时` → 扣子响应慢，调大 `COZE_TIMEOUT_MS`

## 四、前端填入地址（1 分钟）

打开 `index.html`，顶部配置段：

```js
window.CHAT_CONFIG = {
  env: '',
  collection: 'chat_messages',
  rateWindowMs: 60000,
  rateMax: 8,
  pollMs: 2500,
  aiProxyUrl: 'https://xxx-xxx.service.tcloudbase.com/aiProxy',  // ← 填这里
  aiTimeoutMs: 40000
};
```

保存后：本地双击打开或上传到静态托管，消息里带 `@小星` 发出（或写好后点左侧「✦ 小星」按钮）即可。
`aiProxyUrl` 留空则回退本地 8 条规则，功能不缺失。

## 五、改动范围与降级设计

| 文件 | 改动 |
|---|---|
| `index.html` | 仅 `CHAT_CONFIG` 增加两项；`AI.answer` 改为异步优先调云函数；`askAI` 改为 `await`。**UI 段、STORE 段、RATE 段、数据表结构均未改动** |
| `cloudfunctions/aiProxy/index.js` | 新增，云函数本体 |
| `cloudfunctions/aiProxy/package.json` | 新增，无第三方依赖 |

**降级策略**：云函数未配置 → 本地规则；超时 → 本地规则；HTTP 失败 → 本地规则；
扣子返回 `ok:false` → 本地规则。任何情况下点「小星」都有答案，演示不会冷场。

**多轮记忆**：`session_id` 传当前用户的 `ownerId`，同一账号的多轮提问在扣子侧关联上下文。

## 六、答辩讲法（一句话）

> "前端把问题发给云函数，云函数在服务端带鉴权调用扣子智能体，回复落回云数据库；
> 令牌不出服务端，AI 消息与用户消息同表存储、均带 owner_id 归属，断网时自动降级本地规则。"

一句话覆盖**网络分层、安全、数据库设计、容错**四个得分点。

## 七、常见问题

**Q：为什么 Token 不写在 HTML 里？**
A：查看网页源码就能盗用；扣子官方也明确禁止在客户端暴露 Token。云函数环境变量是标准做法。

**Q：本地模式（env 留空）能接扣子吗？**
A：能。云函数是独立 HTTP 服务，和存储模式无关。本地模式下 AI 回复存在浏览器本地存储里。

**Q：Token 过期怎么办？**
A：这个 API Token 是永久有效的。若删除重建，只需改云函数环境变量，前端一行不用动。

**Q：为什么用 async_run 而不是 stream_run？**
A：async_run 两步即可（发起 + 查任务），云函数里实现简单稳定；stream_run 是 SSE 流式，
需要逐块拼接，演示场景没必要，且慢网络下更容易出错。

**Q：重新部署扣子智能体会影响进行中的问答吗？**
A：会。扣子文档说明重新部署会回收沙箱实例，正在运行的异步任务会被终止。演示前先部署完，别中途改。
