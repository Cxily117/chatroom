# 云托管部署指南（单服务：页面 + 接口一起上）

**结论先说：可以直接用云托管，不需要静态网站托管。**

这个项目现在是一个容器搞定两件事：

| 路径 | 谁提供 |
|---|---|
| `/` | `index.html`（前端页面） |
| `/api/*` | Express 接口（注册、登录、消息、好友） |

因为页面和接口同源，浏览器不发跨域请求，`index.html` 里的 `apiBase` 留空就行——页面加载时会自动探测同域的 `/api/health`，通了就显示「🌐 后端 API」。

> 之前那份「静态托管 + 云托管两个服务」的指南是另一条路，现在不推荐：要建两个服务、配跨域、改两次配置。下面这条路只建一个。

---

## 第 1 步：建数据库集合

云开发控制台 → 数据库 → 新建集合 `chat_messages`。

权限选 **「仅管理端可读写」**。后端用管理员身份访问，不受这条规则限制；前端不直连数据库，收权之后即使环境 ID 泄露也读不到数据。

---

## 第 2 步：新建云托管服务

云开发控制台 → 云托管 → 新建服务：

| 字段 | 填什么 | 说明 |
|---|---|---|
| 服务名称 | `chatroom` | 随意 |
| 部署方式 | 代码仓库 / Git 部署 | 授权 GitHub，选仓库 `Cxily117/chatroom`，分支 `main` |
| **目标目录** | **`.`** | ⚠️ 填仓库根目录，**不是** `server`。根目录的 `Dockerfile` 会把页面和接口一起打进去 |
| 端口映射 · 访问端口 | `80` | 对外 HTTP 端口 |
| 端口映射 · 服务端口 | `80` | 与 `Dockerfile` 里 `EXPOSE 80` / `ENV PORT=80` 一致 |
| 实例规格 | 最小规格 0.25 核 0.5G | 课堂演示足够 |
| 最小实例数 | `0` | 没人访问不计费，代价是冷启动 2~5 秒 |

> 如果你之前已经建过一个指向 `server` 目录的服务，两个选择：把目标目录改成 `.` 重新部署，或者直接删掉重建。指向 `server` 的那个镜像只有接口、没有页面，打开域名会是 404。

---

## 第 3 步：配环境变量

同一页面「环境变量」：

| 变量名 | 值 | 必填 |
|---|---|---|
| `TCB_ENV` | 你的环境 ID，如 `slim-galliform-d1gct7tprfa85b9d8` | ✅ |
| `DB_DRIVER` | `cloudbase` | ✅ 不填会退回文件存储，容器一重启数据就没了 |
| `COLLECTION` | `chat_messages` | 可选，默认就是它 |
| `TOKEN_SECRET` | 一串随机字符（越长越好） | ✅ 默认值是公开的，务必改 |
| `PORT` | `80` | 可选，镜像里已设 |
| `ALLOW_ORIGIN` | `*` 或留空 | 可选。同源部署用不到跨域，留空即可 |

生成随机密钥：

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

---

## 第 4 步：部署并自测

点「部署」，首次构建 2~4 分钟。拿到访问域名后：

```bash
# 1. 接口活着吗？顺便看存储驱动
curl https://你的域名/api/health
```

预期：

```json
{"ok":true,"driver":"cloudbase","collection":"chat_messages","users":0,"messages":0,"uptime":5}
```

- `"driver":"file"` → `DB_DRIVER` 没生效，回去补环境变量；
- 502 / 超时 → 端口填错，或容器启动失败，去「日志」看报错。

```bash
# 2. 页面在不在？（应该返回 200 和一大段 HTML）
curl -s -o /dev/null -w "%{http_code} %{content_type}\n" https://你的域名/
```

```bash
# 3. 注册一个账号
curl -X POST https://你的域名/api/register \
  -H "Content-Type: application/json" \
  -d "{\"account\":\"test01\",\"password\":\"123456\",\"nickname\":\"测试\"}"
```

浏览器打开域名 → 注册 → 刷新 → 重新登录。右上角徽章应为 **「🌐 后端 API」**，账号出现在「服务器上的账号」列表里。

---

## 第 5 步（可选）：把静态托管下线

旧方案如果建过静态网站托管，现在不用了，可以在控制台把它停掉/删掉，避免两份页面不一致（改了代码静态那份不会更新，容易看错）。

但**不要删**云开发环境本身，云托管和数据库都挂在这个环境上。

---

## 前端要不要改配置

不用。`index.html` 顶部：

```js
window.CHAT_CONFIG = {
  apiBase: '',   // 留空 = 自动用同源 /api（云托管单服务就是这种）
  env: '',       // 走后端时留空
  ...
};
```

只有当页面和接口**不在同一个域名**时（比如页面放 GitHub Pages、接口放云托管），才需要把 `apiBase` 填成后端域名，并且后端 `ALLOW_ORIGIN` 要配成页面域名。

---

## 排查表

| 现象 | 原因 |
|---|---|
| 打开域名是 404 / 空白 | 目标目录填成了 `server`，镜像里没有 `index.html`。改成 `.` 重新部署 |
| 徽章显示「💾 本地存储」 | 页面没探测到同域 `/api/health`。打开 `域名/api/health` 看是否 200；不是就去查容器日志 |
| 注册报「服务端异常」 | 容器起来了但连不上云数据库，检查 `TCB_ENV` 是否正确、环境里有没有 `chat_messages` 集合 |
| 能注册，换设备登录不上 | `DB_DRIVER` 不是 `cloudbase`，数据写在了容器临时磁盘 |
| 502 | 端口映射不是 80/80，或容器启动失败 |
| 首次打开很慢 | 最小实例数 0 导致冷启动，等几秒；演示前先打开一次热一下 |

---

## 部署完的日常

| 改什么 | 怎么生效 |
|---|---|
| 前端 `index.html` | push 到 `main` → 云托管自动重建镜像 |
| 后端 `server/index.js` | push 到 `main` → 同上 |
| 数据库结构 | 不用建表，字段随写入自动生成 |

只有一个服务、一条流水线，改完 push 就上线。

---

## 费用

云托管按容器 CPU / 内存 / 运行时长计费，有免费额度：
- 最小实例数 `0`：没人访问不计实例费，但有冷启动；
- 设 `1`：常驻，费用高一点，打开即用。

课堂演示建议设 `0`，演示前 1 分钟先打开一次页面。
